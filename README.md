## The afternoon that went wrong

It was supposed to be quick. Pull last week's prediction logs from the feature store, cross-reference with experiment runs, push metrics to monitoring, flag anything unusual.

**14:00** — "Should be quick."
**14:45** — The Feast API needs OAuth. Reading docs for the third time.
**15:30** — Token works in curl. SDK throws 403. Different header format?
**16:15** — Writing a custom paginator for 50k prediction records. Again.
**17:00** — Pipeline crashes. Cursor lost. Full re-fetch. Model training delayed.

This talk is about making that afternoon take four minutes instead of three hours.

## The resolution

```bash
uv run python -m fraud_demo.setup          # start Feast, MLflow, Prometheus
pipeline source add feast --force          # connected, no token needed
pipeline source add mlflow \
    --base-url http://127.0.0.1:5001 \
    --auth-type none --force
pipeline sync run mlflow                   # 13 runs, cursor saved
pipeline sync run mlflow                   # 3 new records — not 13
uv run python -m fraud_demo.run_pipeline   # 4.4s end-to-end
```

```
  ✓ Feast: 50 feature vectors pulled
  ✓ Transactions: 15,000 records (5.5% fraud rate)
  ✓ MLflow: run logged — accuracy=64.7%  recall=43.6%  roc_auc=0.549
  ✓ Prometheus: metrics pushed
  ✓ Linear issue created: https://linear.app/olusola-akinsulere/issue/OLU-11

Pipeline completed in 4.4s.
No connector classes written. No YAML. No SDK imports per source.
```

## What happened behind each command

### `pipeline source add feast`
No preset existed for Feast. The LLM looked at the name, discovered auth type (none — local server), pagination style, and the `/get-online-features` endpoint. A config JSON was written. Nothing else.

### `pipeline source add mlflow`
MLflow is a known provider — it's in the registry. The LLM still ran, filling in gaps. `auth_type: none` because this is a local no-auth server on port 5001. One command. Connected.

### `pipeline sync run mlflow` (first time)
MLflow's search endpoint uses cursor pagination via `page_token`. The connector follows it automatically — 5 runs per page, 3 pages, 13 total. Cursor saved after each page. No pagination code written.

### `pipeline sync run mlflow` (second time)
`Resuming from checkpoint cursor: eyJvZmZzZXQiOiAxMH0=`. Three new runs since last sync. Not 13. The checkpoint picked up exactly where it left off.

### `uv run python -m fraud_demo.run_pipeline`
Two steps run in parallel (Feast features + transaction data), then model training, then MLflow logging, then Prometheus, then Linear — as a DAG. The whole thing in 4.4 seconds.

## The fraud detection dataset

1,000 users · 15,000 transactions · 6 months (Jan–Jul 2026)

Fraud rate **5.5%** — with realistic risk factors: new accounts, low credit scores, no 2FA, international transactions, outlier spend amounts.

Three Feast feature views materialized to SQLite online store:
- `user_account_features` — credit score, account age, 2FA, avg spend
- `user_transaction_counts` — 7-day rolling transaction count

Generated by `fraud_demo/generate_data.py`. No cloud, no BigQuery.

## When auth goes wrong — self-healing

The connector rotates formats automatically when it hits a 403:

```
Try 1: Authorization: Bearer tok_abc123  →  403 ✗
Try 2: Authorization: tok_abc123          →  200 ✓  (format saved)
```

Before any `auth set` prompt, the CLI surfaces exactly where to find the credential:

```bash
pipeline auth set my-feature-store
```
```
Where to find your credentials:
  Docs:         https://docs.my-feature-store.com/authentication
  Auth type:    api_key
  How to get it: Sign in → Account Settings → API Keys → generate key.

Enter API token: ****
✓ Token stored in macOS Keychain — never on disk, never in git.
```

If healing exhausts all formats, the same docs appear alongside the error — no hunting for the right page.

## `--local`: Docker in one flag

For any provider with a Docker image:

```bash
pipeline source add prometheus --local
```
```
  → Pulling prom/prometheus...
  Self-healing: container exists but stopped — restarting...
  ✓ prometheus is ready at http://127.0.0.1:9090
  Auth: none
```

Handles port conflicts, stopped containers, and slow startup automatically. Supported: `mlflow`, `prometheus`, `grafana`, `airflow`, `prefect`. Unknown provider? The LLM finds the image.

## How it works

Five layers — each resolving one entry from the 14:00–17:00 timeline:

| Layer | Resolves | How |
|-------|----------|-----|
| **Registry + LLM** | 14:45 — OAuth docs | Discovers auth type, surfaces docs URL before prompting |
| **Secure Auth** | 14:45 — `.env` risk | Token → OS keychain; never plaintext |
| **Self-Healing** | 15:30 — 403 header | Rotates auth formats, saves winner |
| **Pagination** | 16:15 — custom paginator | Infers cursor / offset / GraphQL from response |
| **Orchestrator** | 17:00 — cursor lost | Checkpoints every batch, parallel DAG |

Code:
- [`connectors/registry.py:86`](python/src/data_pipeline/connectors/registry.py#L86) — `ProviderRegistry.infer_config()`
- [`connectors/llm_discovery.py:445`](python/src/data_pipeline/connectors/llm_discovery.py#L445) — `discover_provider_config()`
- [`connectors/self_healing.py:55`](python/src/data_pipeline/connectors/self_healing.py#L55) — `SelfHealingConnector`
- [`orchestrator/engine.py:34`](python/src/data_pipeline/orchestrator/engine.py#L34) — `PipelineEngine.run()`
