Pattern 1: Retries + Backoff


from tenacity import retry, wait_exponential, stop_after_attempt

@retry(
    wait=wait_exponential(multiplier=1, max=60),  # 1s → 2s → 4s... → 60s
    stop=stop_after_attempt(3),
    retry=retry_if_exception_type((TransportError, RateLimitError)),
)
async def request(self, method, path, **kwargs):
    response = await self._client.request(method, path, **kwargs)

    if response.status_code == 429:  # Rate limited
        retry_after = float(response.headers.get("Retry-After", "60"))
        await asyncio.sleep(retry_after)
        raise RateLimitError(retry_after)   # → tenacity retries

    response.raise_for_status()
    return response
TIMING: 17:30. Point to @retry decorator: "Three lines. That's it." Walk the wait_exponential: "1 second, then 2, then 4... capped at 60. Classic exponential backoff." Point at the 429 block: "Rate limited? The API tells us exactly how long to wait. We sleep that exact duration. No guessing." "MLflow self-hosted might not have rate limits. W&B's cloud API does. This handles both transparently."

Takeaways

Your checklist

Building self-configuring connectors

  • Registry of known patterns (accelerators, not requirements)
  • LLM-driven discovery for unknown APIs — with fallback
  • OS keychain for credentials (never .env, never git)
  • Self-healing auth — try multiple formats before failing
  • Universal pagination — cursor, offset, link-header, GraphQL

  • Structured logs at every state transition
  • Incremental by default, full-refresh as an escape hatch
